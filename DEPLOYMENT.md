# Deployment

Minimal production-shape deployment: FastAPI + arq workers + Postgres + Redis, TLS terminated at a reverse proxy in front of the Python processes.

## Required environment

Every one of these must be set at deploy time — the app has no fallbacks for them and boots into a validation error otherwise (deliberate; see `Settings._enforce_environment_invariants`).

| Var                              | Example                                                     | Notes |
| -------------------------------- | ----------------------------------------------------------- | ----- |
| `ENVIRONMENT`                    | `production`                                                | Turns on the production invariants (`debug` must be off, `cors_origins` explicit, blocklist fails closed on Redis outage). |
| `JWT_SECRET`                     | 32+ character random string                                  | Rotate via a rolling deploy that briefly accepts both old and new (out of scope for this repo — track it in Vault/AWS Secrets Manager, not env). |
| `DATABASE_URL`                   | `postgresql://user:pw@pgbouncer:6432/rockfallguard`         | The DSN normaliser in `app/db/engine.py` rewrites `postgres://` / `postgresql://` → `postgresql+asyncpg://` so both work. |
| `REDIS_URL`                      | `redis://redis:6379/0`                                      | Used by rate limiter, cache, blocklist, arq queue, emergency stream. |
| `CORS_ORIGINS`                   | `https://ops.rockfallguard.example`                         | Comma-separated. `Settings` refuses to boot in production with an empty list or `"*"`. |
| `TRUSTED_HOSTS`                  | `ops.rockfallguard.example,ops2.rockfallguard.example`      | Rejected if it contains `"*"` in production. |
| `SMTP_HOST` / `SMTP_USER` / `SMTP_PASSWORD` | (your MTA credentials)                             | Absent = dispatcher runs in "simulated" mode; alerts log but no email goes out. |
| `TWILIO_ACCOUNT_SID` / `TWILIO_AUTH_TOKEN` / `TWILIO_FROM_NUMBER` | (Twilio project creds)                    | Same as SMTP; absent = SMS is simulated. |

## Process shape

Two long-running Python processes per pod:

1. **API** — `python -m uvicorn main:app --host 0.0.0.0 --port 8005` (that's what the Docker `CMD` runs after `alembic upgrade head`).
2. **Worker** — `arq app.workers.settings.WorkerSettings`, one or more replicas scaled by queue depth.

Both mount the same shared volume for `data/uploads/` (the worker reads what the API wrote). On Kubernetes that's typically an `emptyDir` shared inside the pod, or an EFS/PVC across pods.

## TLS termination

The Python processes speak plain HTTP; TLS terminates at a reverse proxy in front. Two patterns known to work:

* **Nginx / Caddy / Traefik in the same pod as a sidecar** — proxy listens on 443 and forwards to `localhost:8005`. Cert renewal via Caddy's built-in ACME or cert-manager on k8s.
* **Cloud load balancer (ALB / GCLB / Azure App Gateway)** — terminates TLS at the edge, forwards HTTP to a `NodePort` / `Service`. Usually the simplest for a real deployment because cert management belongs to the cloud IAM console.

Do **not** try to run uvicorn on 443 with its `--ssl-keyfile` flag in production — it works, but there's no cert-rotation story and no HSTS/OCSP-stapling story. Keep TLS out of the Python process.

`app/core/middleware.SecurityHeadersMiddleware` already emits `Strict-Transport-Security` in production, `X-Frame-Options: DENY`, `Referrer-Policy`, and `Content-Security-Policy` for XSS defense-in-depth. Wire it in via `install_middleware` when you take the app into production (Step 7 wired `RequestContextMiddleware` and `BodySizeLimitMiddleware` but left the full CORS/security stack out because the existing test contract expects `allow_origins=["*"]`).

## Probes

Kubernetes-style probes are wired on distinct paths:

* `GET /health/live` — process is alive. Restart the pod if this fails.
* `GET /health/ready` — deps (DB, Redis) reachable. Pull the pod from the LB target set if this fails; do NOT restart it (a Redis blip shouldn't cycle every pod).
* `GET /api/health` — legacy aggregated shape kept for the existing frontend / test contract.

The Docker `HEALTHCHECK` hits `/health/ready` because Docker's healthcheck maps cleanly onto readiness, not liveness.

## Observability

* `GET /metrics` — Prometheus scrape endpoint. Metrics defined in `app/core/metrics.py`; label cardinality is fixed and reviewable in one place.
* Every log line is JSON with a `correlation_id` field, sourced from `X-Request-ID` if present or generated by `RequestContextMiddleware`. In production, ship via `stdout` → your log aggregator (Loki, CloudWatch, Datadog); don't log to files inside the container.
* When the app grows to multiple workers, switch `prometheus_client` to multiprocess mode (`PROMETHEUS_MULTIPROC_DIR`); see the follow-ups list in `app/core/metrics.py`.
